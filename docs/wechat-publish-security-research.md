# 预览 HTML 安全性研究记录

> 状态：完成现状盘点与方案比较；暂不引入 sanitizer、CSP 或 sandbox 改变既有输出。
> 日期：2026-08-19

## 1. 当前事实

### Markdown 原始 HTML

`src/markdown-core.ts` 使用 Markdown-it 的 `html: true`。因此，笔记中的原始 HTML 会进入共享渲染核心；当前核心没有主动删除：

- `<script>`、`<style>` 等标签；
- `onclick` 等事件属性；
- 原始 HTML 中的 `javascript:`、`data:` 等危险 URL；
- 其他非 Markdown-it 生成的 HTML 属性。

这是当前“保留普通 HTML 支持”的既有行为，不应在没有兼容性样例时悄然改变。

### Preview 路径

`src/main.ts` 将渲染结果嵌入本地 HTTP 预览页。预览页本身包含插件生成的工具栏脚本，用于桌面/手机视图和浅色/深色切换；它不是笔记内容提供的脚本。

预览页运行在本机浏览器中。若用户把不可信的 HTML 粘贴进笔记，原始 HTML 可能被浏览器解释，因此“本地、自写笔记”与“外部不可信 Markdown”是不同的威胁模型。

### Copy 路径

Copy 路径将渲染 HTML、主题 CSS 和经过 juice 处理的结果写入 Electron 剪贴板。Copy 不写入本地图片 Base64，而是使用 `【图片：路径】` 占位符；这条边界与 HTML 安全性是两个独立问题。

当前没有自动上传、微信 API 或账号凭证逻辑。微信公众号编辑器最终如何过滤 HTML，也不能代替插件自身的输入边界定义。

## 2. 威胁模型

暂时将风险分为三档：

| 来源 | 典型情形 | 当前优先级 |
|---|---|---:|
| 自己在本地编写的笔记 | 普通 Markdown、Callout、少量原始 HTML | 低 |
| 从网页或他人处复制的 Markdown | 带 `<script>`、事件属性或危险链接 | 中 |
| 预览页被当作通用浏览器页面打开 | 内容含主动脚本或外部资源 | 中/高 |

当前插件的主要目标是个人本地写作与公众号复制，不是通用的“不可信 Markdown 在线预览器”。如果未来要支持后者，应先明确是否允许原始 HTML、脚本和外部资源。

## 3. 候选方案比较

### 最小 CSP

在预览页增加 CSP，可以限制脚本来源、对象、外部资源和连接目标。难点是插件当前预览页确实需要内联脚本和内联样式；如果直接禁止 `unsafe-inline`，必须先改造工具栏脚本和样式加载方式。CSP 也不能单独清理 Copy 到剪贴板的 HTML。

### HTML 标签/属性 allowlist

在共享核心之后、Preview/Copy 分叉之前清理原始 HTML，允许文章需要的有限标签和属性，拒绝脚本、事件属性及危险 URL。这能同时约束两条输出链路，但会改变用户当前的原始 HTML 支持，必须先准备兼容性样例和明确的 allowlist。

### sandbox iframe

把预览内容放入 sandbox iframe，可以把预览运行环境与宿主页面隔离。代价是调整当前预览页的 DOM、脚本通信和样式注入；它只解决 Preview 隔离，不能直接解决 Copy HTML 的输入安全性。

## 4. 暂定结论

本阶段只完成事实和方案记录，不改变渲染输出：

1. 不把“微信公众号会过滤某些标签”当作插件安全策略。
2. 不直接引入复杂 sanitizer，以免破坏 Callout、MathJax SVG、用户自定义 HTML 和现有主题。
3. 若要推进，优先建立最小危险样例和用户需求清单，再比较 allowlist 与 CSP；sandbox 作为 Preview 专项隔离方案。
4. Copy 路径继续保持图片占位符边界，不引入 Base64 或微信 API。

## 5. 后续启动条件

- 出现可复现的脚本执行、危险链接或外部资源问题；
- 需要支持来自不可信来源的 Markdown；
- 明确列出公众号文章必须保留的原始 HTML 标签和属性；
- 完成 Preview/Copy 两条路径分别的安全回归样例。
